A dropped socket is no longer the end of a conversation: the newest resumption handle is kept, and reopening with it continues the SAME session, which together with contextWindowCompression is what makes a session outlive a 25-minute study block. Three things shape how that is written. The close callback can land off the main thread, so OnClose/OnError only raise a volatile flag and every Unity call — Microphone.End, Time.unscaledTime, the OnDisconnected fan-out — happens in Update, per the voice rule about marshaling the receive path. Reconnect is refused unless the socket has succeeded AT LEAST ONCE (_everConnected, set on setupComplete): retrying a bad key or a retired model id forever is a loop with no way out, while retrying a connection that has already worked is just the network. And Disconnect() exists so a deliberate shutdown does not look like a drop — it is the only thing that stops the retry, and OnDestroy goes through it. Backoff is 0s then 1, 2, 4, 8... capped by VoiceSessionConfig.ReconnectBackoffMaxSeconds, which the CALLER supplies so this class still reads no config asset but GeminiApiConfig. ResumedFromHandle tells the caller the reconnected session is the same conversation, so the user is not greeted twice. The send queue is cleared on every open, since a frame queued against a dead socket is meaningless to the new one.
