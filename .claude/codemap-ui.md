Assets/Scripts/UI/PushToTalkButtonView.cs | the app's one button: four states, two sprites | sys: UI | api: PttButtonState{Offline,Connecting,Ready,Listening}; button; image; idleSprite; listeningSprite; connectingDim; Pressed; SetState(PttButtonState) | dep: - | used: RoomSessionController,SessionUiSetup | crit: K2 | note: the first code in the UI system, and it depends on NOTHING - not Voice, not Session, not even an interface. The plan imagined this component holding an IVoiceSession; inverting it instead (the view reports a press, Bootstrap decides what a press means) costs one event and buys a UI shard with zero arrows out of it, which is the strongest form of the one-way rule the blueprint asks for. It also avoids the real problem with the other shape: what a press means depends on session state that RoomSessionController already holds, so a view that decided for itself would need a second copy of it. Offline and Ready deliberately paint the same - to the user both are "press to talk", and the first press happening to open the socket is not worth explaining on screen - which is also why there are two sprites for four states and no third asset was commissioned; Connecting is the idle sprite dimmed. The dim goes on image.color (the Graphic) rather than replacing the Button's transition, because Button's ColorTint works on the CanvasRenderer: the two multiply, so dimming does not cost the press feedback. interactable is dropped only while Connecting, and that is the guard that matters - a press there would reach a Connect() that must not run twice. SetState early-outs on an unchanged state, so RoomSessionController can push it every frame for one enum compare, and Start() repaints once so the button never opens on whatever sprite the scene was saved with | h:0ceeb7ba
