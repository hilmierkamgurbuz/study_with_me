# Voice domain rules

- `GeminiLiveVoiceSession` is the only thing that owns the WebSocket, the mic capture loop, and the playback ring buffer. Everything else talks to it only through `IVoiceSession`.
- Turn boundaries are client-driven: `setup.realtimeInputConfig.automaticActivityDetection.disabled = true` always; every listening window (push-to-talk hold, or an auto-open window) is wrapped in explicit `activityStart`/`activityEnd` messages. Do not re-enable server-side auto-VAD without updating this rule and the plan's Architecture section — it was deliberately disabled because push-to-talk is already the app's real "is the user talking" signal.
- A received `toolCall` always gets an immediate `toolResponse` in the same handling pass — an unacknowledged tool call can stall the model's turn.
- Barge-in (flushing the local playback ring buffer and sending a fresh `activityStart`) happens synchronously on the calling thread the moment PTT is pressed or text is sent — it never waits on a network round trip. It is two halves, and removing the second one brings back D-059: the flush disposes of audio that has already arrived, and a drop window disposes of the tail the server keeps sending until it processes the interruption. That window is armed only while the server actually has a turn in hand (otherwise a press made in silence would eat the beginning of the next answer), it closes on the `serverContent.interrupted` acknowledgement, and its time bound exists only for the case where that acknowledgement never comes. `interrupted` is handled before the model turn carried in the same message, never after.
- The receive loop runs on a background thread, but the installed package posts messages and events to the `SynchronizationContext` it captured at construction — Unity's main thread — so `OnMessage`/`OnOpen`/`OnError`/`OnClose` bodies may touch UnityEngine APIs directly, and the `Update()` `DispatchMessageQueue()` poll is a fallback for the no-context case rather than the delivery mechanism (`engine-facts/voice-audio.md`). Do not add a second marshaling queue for the WebSocket side; do not remove the close FLAG either — `OnClose`/`OnError` raise it and nothing else so that "the connection is gone" has one owner, handled once in `Update()`. The one genuinely off-thread path is the `AudioClip` `pcmReaderCallback`, which runs on the audio DSP thread and touches nothing but the ring buffer.
- A dropped socket is reconnected by `GeminiLiveVoiceSession` itself, using the newest session-resumption handle; no caller reconnects by calling `Connect` again, and `Disconnect()` is the only way to say a close was meant. `setup.contextWindowCompression.slidingWindow` and `setup.sessionResumption` stay enabled together — they are what keeps a conversation alive past the audio-only session duration cap, and a study block is expected to outlive a single connection.
- The streaming-playback ring buffer is fixed-size and pre-allocated — no allocation inside the `AudioClip` `pcmReaderCallback`, which runs on Unity's audio DSP thread. It is sized for a whole turn arriving at once, not for network jitter, because the server sends audio faster than it is spoken. When it is full it drops the newest samples and logs; it never advances the read cursor to make room, which is what shredded one sentence into another (D-059).
- One live socket at a time, enforced rather than assumed: a socket being replaced is closed first, and every socket callback checks that it still speaks for the current connection. The package delivers through Unity's `SynchronizationContext`, so an abandoned socket is not a silent one (D-060).
- Structured decisions (session duration, break-offer intent, onboarding profile fields) are resolved via Gemini function-calling tools declared per session state, never by string/keyword matching on transcript text — this is what makes decision parsing multilingual for free.
- Model IDs for the Live API are preview-tier and rotate; never hardcode one without checking `ai.google.dev/gemini-api/docs/models/live` first, and keep the current ID in exactly one place (`GeminiApiConfig`).
